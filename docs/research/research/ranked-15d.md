## Combined architecture implications

1. Agent front door with both A2A and MCP. SAP takes inbound A2A, Coupa exposes MCP tools. Put both adapters, plus every payment protocol (AP2, ACP, UCP, x402, MPP), behind one gateway so protocol churn stays contained.
2. Policy engine outside the model is the only route to money. The model proposes a payment intent. Code checks payee against vendor master, limits, mandate and segregation of duties.
3. Separate mandate from rail. Store a signed mandate (AP2 style) carrying PO, contract price, net terms and approval chain, since public protocols lack these B2B primitives.
4. Rail router by cost, speed, corridor and counterparty readiness across card, ACH, RTP, stablecoin and tokenized deposit, with issuer and chain choice behind an adapter.
5. Agent identity as a first class service. Register each agent, bind it to an ERP role and a scoped, revocable token or wallet key, and verify Visa TAP and Mastercard KYA at the edge.
6. Invoice first, ERP as system of record. Start with invoices already approved in SAP or Oracle, as the Visa pilot does, and never bypass suite audit for posting or payment.
7. Maker and checker split. The agent drafts, a human or second control releases, and autonomy widens step by step on risk scores.
8. Compliance before send on final rails. Wallet screening, Travel Rule exchange, sanctions checks, allowlists and holds run before any stablecoin transfer, ready for the pending BSA, AML and OFAC rule.
9. Budgets, metering and multiple ramps. Budget envelopes cover per-call x402 charges and agent cost per transaction, and each corridor has more than one licensed ramp with wire fallback.
10. Evidence and reconciliation built in. Every payment carries mandate, policy result, approver and rail reference (card auth or tx hash), reconciled daily into the ERP with invoice, entity and FX data.
