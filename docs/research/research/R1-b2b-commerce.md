## 5 key implications for an architecture

1. Use A2A for agent to suite calls and MCP for tool access. SAP now takes inbound A2A. Coupa exposes MCP tools. The design needs both adapters behind one gateway.
2. Build your own B2B layer for contract price, PO, approval chain and net terms. The public protocols do not carry them. Model them as signed mandates the buyer agent presents.
3. Make agent authority explicit. Suites still bound actions by the signed in user and admin onboarding. Issue scoped, revocable credentials per agent with spend limits and audit logs.
4. Treat the procurement suite as the system of record and the agent as an overlay. ORO, Procol and Coupa write back all keep audit inside the suite. Do not bypass it for payment or invoice posting.
5. Plan for gated and uneven access. Coupa MCP setup is not public and Oracle details are unclear. Keep a fallback path through cXML punchout and existing APIs, and meter agent cost per transaction.
