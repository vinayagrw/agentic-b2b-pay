Failure modes. Open a card.

  

    
Replay
Effect. Duplicate or forged auth inside the signature window.
Fix. Replay cache for the full validity window, bound to the idempotency key.

    
Revocation
Effect. Charge after the user withdrew consent.
Fix. Revocation events in the ledger. List checked before every auth. Fail closed when stale.

    
Impersonation
Effect. Unknown operator gets high limits.
Fix. A signature proves key control only. Unregistered agents get the lowest tier.

    
Prompt injection
Effect. Valid mandate over an unwanted cart, injected upstream.
Fix. Cart-to-intent rules and step-up consent. Agent text never reaches a decision function.

    
Key directory poisoned
Effect. Forged agent requests.
Fix. Pinned sources, signed key sets, alert on unexpected rotation.

    
Retry storm
Effect. Auth load and duplicate charges.
Fix. Mandatory idempotency keys, per-agent rate limits, circuit breaker.

    
Ledger write fails
Effect. Lost evidence.
Fix. Outbox pattern, reconcile, block when ledger lag passes a threshold.

    
Bad deploy
Effect. Runaway behaviour, Knight Capital style.
Fix. Feature flags, canary, kill switch per agent, merchant and global.

ch.08a / shipped in the B2B demo

  
New controls in the demo

  
All on sandbox or simulated money. Tap a tile for detail. Visa with BILL and Billtrust is still a pilot.

  

    
Bank-change check
A supplier asks to change bank details. The change waits for a call-back to a known number, then a cooling-off hold, then a second person signs off (maker-checker).

    
Mandate-bound card
A virtual card issued for one approved order. It approves a charge only for that order and its exact amount. The issuer is simulated or Stripe Issuing in test mode. It is not a card network product.

    
Dispute evidence
One record per paid order: mandate, approvals, match result and payment events. Card numbers show the last 4 digits only.

    
Early pay
Invoices show payment terms, the pay-by date and the early-pay discount. A second admin approves a pay-early plan. Savings are demo figures.

    
Tariff scenario
Duty fields on order lines feed a 12 week cash forecast, with and without exclusions. Duty rates are user inputs. No live tariff feed. The notice names both 9 and 10 January 2027 as the end date, so the date is a setting.

    
Credit line
A simulated credit line. The operator sets limit and rate. Each draw needs a maker and a checker. No real lender.

    
Chat approvals
Approvers see an order card in Slack or Teams. Same rules and limits as the app. Mock preview only.

    
Copilot charts
Ask a question, get a chart from fixed read-only tools, with sources. Export as PNG.

  







  
ch.08b / decisions

  
Five decisions on record

  

    
ADR-1. Edge adapter
Decision. Option A, with a canonical agent payment object built to seed B.
Consequence. Fast and reversible. In PCI scope as connected-to. Review when scheme liability rules land or the pilot shows no dispute value.

    
ADR-2. No LLM on auth
Decision. LLM async only, on de-identified data. No AI in the CDE.
Consequence. Predictable latency and audit. LLM value sits in disputes and copilots.

    
ADR-3. Mandate ledger
Decision. Append-only ledger outside the CDE. Mandate hash, agent ID, protocol version, decision. No PAN.
Consequence. Evidence ready for any rule. One more store to run.

    
ADR-4. Scheme KYA
Decision. Hybrid. Consume scheme directories for keys and tiers, keep a thin local tier map.
Consequence. Less identity liability. Partner uptime handled by caching within key expiry.

    
ADR-5. Versioned adapters
Decision. Adapters normalise to one object, version pinned and canaried.
Consequence. Two protocols in year one. Deprecation policy per adapter. New protocol only when a scheme or top merchant asks.
